# gost-docx

Это движок, который собирает учебные работы из обычного Markdown в готовые **docx + pdf**, уже оформленные по ГОСТу и Положению СПбГЭУ. Пишешь текст в `.md` — движок делает всё остальное.

Сделал я его, потому что оформлять работы руками в Word — это боль. Шрифт, поля, интервалы, красная строка, содержание, номера страниц, подписи к таблицам — каждый раз одно и то же, и каждый раз что-нибудь съезжает. Особенно содержание: поправил абзац в середине — и все номера страниц поехали, сиди пересобирай вручную. Меня это достало, вот я и вынес текст отдельно от оформления. Содержание работы живёт в `.md`-файле, а всю возню со стандартом берёт на себя `engine.py`. Я правлю текст, а не код.

## Что делает

- **Оформляет по стандарту** без меня: Times New Roman 14, интервал 1,5, поля 30/10/20/20 мм, красная строка 1,25 см, текст по ширине.
- **Содержание с настоящими номерами страниц.** Тут вся хитрость. Движок собирает черновой docx, гонит его в pdf, вычитывает из pdf, на какой странице реально оказался каждый заголовок, и пересобирает содержание уже с точными номерами и точками-лидерами. То есть цифры не выдуманы на глаз, а взяты из готового файла.
- **Нумерация страниц** внизу по центру, стартует с той страницы, с какой нужно (по умолчанию с 3-й — после титульника и содержания).
- **Таблицы** оформляет по ГОСТу: подпись «Таблица N – …», кегль 12, жирная шапка, все границы.
- **Рисунки** — подпись «Рисунок N – …» по центру.
- **Формулы** — директива `@center`: формула по центру, номер «(1)» уходит к правому краю, абзац «где …» после неё не отрывается.
- **Передние страницы** (титул, реферат, задание) собираются из текстового файла с директивами: `front_file` в `meta.json`. Нумерация страниц идёт с титула, номер на нём не печатается; в тексте работает подстановка `{PAGES}` — итоговый объём подставляется сам, после чего движок при необходимости делает ещё один проход.
- **Продолжение таблиц:** если таблица разорвалась между страницами, на следующей странице появляется «Продолжение таблицы N» (`table_continuation`).
- **Настройка таблиц:** ширины колонок и кегль прямо в подписи (`| w=4,10,3 | s=10`), таблица держится на одной странице.
- **Тире и маркеры по Положению:** маркер списка — тире, тире в подписях можно переключить на длинное (`caption_dash`), автоперенос слов включён в теле текста и выключен в заголовках, титуле и таблицах.
- **Список источников** нумерует из `meta.json` ровно в том порядке, в каком я его задал.
- **Считает объём:** после сборки говорит, сколько вышло страниц, и сверяет с целевым диапазоном — удобно, когда работа должна быть «на 15–20 страниц».
- На выходе сразу и `docx`, и `pdf`.

Чего он намеренно не умеет: рисовать титульный лист сам по ГОСТу (его содержимое задаётся файлом `front_file`), автосортировку источников по ГОСТу (подаю уже отсортированными) и хитрые объединённые ячейки в таблицах. Диаграммы рисую отдельно (тем же matplotlib) и вставляю картинкой через `@image`.

## Стек

- **Python 3.9+**
- [`python-docx`](https://python-docx.readthedocs.io/) — генерация `.docx`.
- [`pypdf`](https://pypdf.readthedocs.io/) — чтение готового pdf для определения номеров страниц.
- [**LibreOffice**](https://www.libreoffice.org/) (`soffice`) — headless-конвертация `docx → pdf`.

## Установка

```bash
# 1. Python-зависимости
pip install -r requirements.txt   # или: pip install python-docx pypdf

# 2. LibreOffice (для конвертации в pdf)
# macOS:
brew install --cask libreoffice
# Debian/Ubuntu:
sudo apt install libreoffice
# Windows: скачать с libreoffice.org
```

Движок сам ищет `soffice` в стандартных местах (macOS / Linux / Windows) и в `PATH`. Если LibreOffice установлен нестандартно — укажите путь явно через переменную окружения:

```bash
export SOFFICE_PATH="/путь/к/soffice"
```

## Использование

```bash
python3 engine.py <исходник.md> <meta.json>

# быстрый черновик без двухпроходного содержания:
python3 engine.py <исходник.md> <meta.json> --once
```

Пример (в репозитории лежит готовый комплект в `example/`):

```bash
python3 engine.py example/rabota.md example/meta.json
```

Результат — `docx` и `pdf` в папке, указанной в `output_dir`, плюс отчёт по объёму в консоли.

## Формат исходника (`.md`)

```
# ВВЕДЕНИЕ                     ← H1. Если заголовок начинается с цифры — станет ЗАГЛАВНЫМИ.
                                 Каждый H1 начинается с новой страницы.
## 1.1 Подраздел               ← H2
Обычная строка = абзац (красная строка, по ширине). Ссылки на источники: [1; 2].
Пустая строка разделяет абзацы.
- пункт маркированного списка

@table Таблица 1, подпись таблицы
Заголовок1 | Заголовок2        ← первая строка = шапка (жирная)
ячейка | ячейка
@endtable

@table Таблица 2, подпись | w=4,10,3 | s=10   ← необязательно: доли ширин колонок и кегль таблицы
@image path/chart.png | 12 | Рисунок 1, подпись рисунка   ← ширина в сантиметрах
@center y = a * x + b      (1)   ← формула по центру, номер (после 2+ пробелов) — справа
@pagebreak                     ← принудительный разрыв страницы
@sources                       ← вставить нумерованный список источников из meta.sources
```

Заголовок **СОДЕРЖАНИЕ** движок строит сам — в `.md` его писать не нужно. Пункты содержания берутся из `#` / `##` автоматически.

## `meta.json`

```json
{
  "output_dir": "./out",
  "output_name": "Пример документа.docx",
  "target_pages": [15, 20],
  "toc_start_page": 3,
  "sources": [
    "Автор. Заглавие. – Город : Издательство, год. – с.",
    "..."
  ]
}
```

| Поле | Назначение |
| --- | --- |
| `output_dir` | Куда сохранить результат (относительный или абсолютный путь; `~` раскрывается). |
| `output_name` | Имя выходного `.docx` (одноимённый `.pdf` рядом). |
| `target_pages` | `[min, max]` — целевой диапазон объёма; движок предупредит, если вне его. Необязательно. |
| `toc_start_page` | С какой страницы начинается нумерация (по умолчанию 3). |
| `sources` | Список источников в готовом порядке; вставляется по директиве `@sources`. |
| `front_file` | Файл с передними страницами (титул, реферат, задание); формат — ниже. |
| `page_start` | С какого номера начать нумерацию при `front_file` (по умолчанию 1). |
| `pages_hint` | Что подставить в `{PAGES}` на первом проходе. |
| `table_continuation` | `true` — подписывать «Продолжение таблицы N» на следующей странице. |
| `table_font_size`, `table_left_cols`, `table_keep_together` | Кегль таблиц (12), номера колонок с выравниванием влево, держать таблицу целиком на странице (`true`). |
| `caption_dash` | Тире в подписях таблиц и рисунков (по умолчанию «–»). |
| `caption_plain` | `true` — подписи обычным шрифтом, без курсива и кегля 12. |
| `bullet_dash` | Маркер списка — тире (`true`); `false` — «•». |
| `hyphenation` | Автоперенос в теле текста (`true`). |
| `sources_left` | Выравнивать список источников по левому краю. |
| `no_toc`, `no_h1_break` | Не строить содержание; не начинать каждый раздел с новой страницы. |
| `toc_line_spacing`, `toc_right_indent_cm` | Интервал и правый отступ содержания. |
| `right_margin_cm` | Правое поле (по умолчанию 1 см). |
| `student.fio` | Попадает в свойства документа (автор). Необязательно. |

### Файл передних страниц (`front_file`)

Одна директива — одна строка: `@c` / `@l` / `@r` / `@j` — выравнивание по центру / слева / справа / по ширине (`@j` — с красной строкой и интервалом 1,5), после буквы необязательно кегль и `b` для жирного (`@c16b ТЕКСТ`), `@sp` — пустая строка, `@page` — разрыв страницы, `{PAGES}` — объём работы. Пример — `example/front.txt`, запуск:

```bash
python3 engine.py example/rabota.md example/meta-front.json
```

## Как это работает внутри

1. `parse_source()` разбирает `.md` в список типизированных блоков (заголовки, абзацы, списки, таблицы, изображения, формулы, директивы).
2. `build()` собирает `.docx` через `python-docx`, применяя стили стандарта; передние страницы берутся из `front_file`, содержание строится из заголовков.
3. `to_pdf()` конвертирует `docx → pdf` через headless LibreOffice.
4. `detect_pages()` читает pdf через `pypdf` и находит фактическую страницу каждого заголовка.
5. Если включено `table_continuation`, `detect_table_splits()` находит разорванные таблицы и сборка повторяется с подписями продолжения.
6. `build()` вызывается второй раз — теперь содержание получает реальные номера страниц. Итоговый `pdf` пересобирается, печатается отчёт по объёму.
